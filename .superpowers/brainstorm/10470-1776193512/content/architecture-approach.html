Architecture for Role Overlays — which approach?

How resume content is stored and customized per role

A

Inline Role Sections

Master resume stores ALL bullets in one document. Each role's overlay adds: role-specific summary, reordered bullets (with priority scores), and keyword additions. Single table, role is a field on each bullet.

Simple data model. Great for reordering and highlighting existing content. Harder to write entirely new role-specific paragraphs.

B

Separate Overlay Table

Master resume is pristine. Each target role has an overlay record with: custom summary, bullet priority map, keyword set, and optional custom bullets. Resume renderer merges master + overlay at display/export time.

Cleaner separation. Master never gets "polluted" with role-specific edits. More complex rendering logic.

C

Generated Variants (on-demand)

Master is the source. Role overlay defines a "prompt" (target role keywords + emphasis rules). Variants are generated by AI and saved as named snapshots. Overwrites regenerate the snapshot.

Maximum freshness (always re-optimized). Less "owned" feel. Best if AI is trustworthy for this. Variant history becomes important.
